## 🌿 System Overview & Architecture

AgriPulse is an **Intelligent Decision Support System (IDSS)** designed to solve key operational challenges in Sri Lankan tea smallholder supply chains:
- **Farm Resource Allocation**: Allocating limited fertilizer and irrigation pumps.
- **Spoilage Intelligence**: Sorting and prioritizing harvested tea batches by spoilage risk.
- **Urgent Collection Dispatch**: Routing collection trucks to high-priority harvest batches using Dijkstra shortest-path calculations.
- **Supply Network Throughput**: Calculating daily tea carrying limits and identifying transport bottlenecks.

The frontend serves as the unified decision support dashboard, rendering algorithmic outputs generated by specialized Spring Boot backend modules.

## 🔌 Backend Service Ports & Proxy Mapping

To prevent CORS issues and allow all 3 Spring Boot backends to run simultaneously on separate ports, Vite uses proxy rules:

| Module / Service | Backend Port | Vite Proxy Path | Target URL |
| :--- | :--- | :--- | :--- |
| **Module 3 Backend** | `8080` | Direct (`VITE_API_BASE_URL`) | `http://localhost:8080` |
| **Module 4 Backend** | `8081` | `/module4-api` | `http://localhost:8081` |
| **Dispatch & Route Engine** | `8082` | `/dispatch-api` | `http://localhost:8082` |

## 📖 Detailed Page-by-Page Breakdown

### 🚚 1. Dispatch & Route Engine (Port 8082)

#### 📍 `LiveDispatchPage.jsx` (`/dispatch`)
- **What it does**: Functions as the primary command center for tea collection dispatchers.
- **Key Features**:
  - **Truck Node Selector**: Allows clicking nodes (C1 to C6) to set the truck's current position.
  - **Max-Heap + Dijkstra Route Guide**: Calls `GET /api/v1/dispatch/next-route?truckNode=...` to automatically fetch the highest priority ready batch (e.g. B-102 at C6) and compute the shortest accessible path.
  - **Interactive Path Visualizer**: Displays the sequence of nodes (e.g., `C1 -> C2 -> C5 -> C6`) with distance costs and incline penalties.
  - **Mark Batch as Collected**: Clicking **"Mark Batch as Collected"** (`PUT /api/v1/dispatch/batches/{id}/collect`) updates batch status to `COLLECTED` in PostgreSQL and automatically recalculates the optimal route to the next priority target.
  - **Reset / Seed Database**: Clicking **"Reset / Seed Database"** (`POST /api/v1/dispatch/seed-data`) populates PostgreSQL with nodes C1-C6, 7 roads, and initial batches B-102 and B-091.

#### 🧮 `RouteCalculatorPage.jsx` (`/dispatch/calculator`)
- **What it does**: Provides an in-memory playground for logistics managers to simulate custom scenarios without affecting live database records.
- **Key Features**:
  - Add/remove custom ready harvest batches with custom priority scores.
  - Modify custom road edge distances, incline factors, road quality penalties, and monsoon state flags.
  - Calls `POST /api/v1/dispatch/calculate-route` to view step-by-step algorithm output and weighted cost breakdown.

#### 🚧 `RoadControlPage.jsx` (`/dispatch/roads`)
- **What it does**: Controls live road hazards and open/closed statuses in PostgreSQL.
- **Key Features**:
  - Displays a table of PostgreSQL road segments (C1-C2, C2-C3, C4-C6, etc.).
  - Toggle **Open/Closed** state or **Monsoon Weather Hazard** (`PUT /api/v1/dispatch/roads/{id}/status`).
  - Instantly observe how closing a road or enabling monsoon mud penalties forces Dijkstra to recalculate alternative paths.

---

### 🌐 2. Tea Supply Network Analysis (Module 3 · Port 8080)

- **`FlowAnalysisPage.jsx` (`/network`)**: Calculates daily tea delivery throughput capacity using the Ford-Fulkerson algorithm.
- **`BottlenecksPage.jsx` (`/network/bottlenecks`)**: Highlights saturated transport links that restrict total throughput.
- **`ScenarioLabPage.jsx` (`/network/scenarios`)**: Compares what-if scenarios (road upgrades, capacity reductions, link closures).
- **`GraphManagerPage.jsx` (`/network/graph`)**: Interactive graph node and connection editor.
- **`BenchmarksPage.jsx` (`/network/benchmarks`)**: System runtime performance benchmarks.

---

### 🍂 3. Spoilage Risk Intelligence (Module 4 · Port 8081)

- **`RiskRankingPage.jsx` (`/spoilage`)**: Ranks harvested tea batches using risk scoring combined with Merge Sort, Insertion Sort, and Bubble Sort.
- **`PriorityQueuePage.jsx` (`/spoilage/priority`)**: Real-time Max-Heap priority queue operations (Enqueue, Peek Top, Pop Top, Refresh).
- **`SpoilageBenchmarksPage.jsx` (`/spoilage/benchmarks`)**: Runtime and memory benchmarks comparing sorting vs Max-Heap retrieval.

---

### 📊 4. Operations Overview Dashboard (`/`)

- **What it does**: Executive summary dashboard displaying system-wide operational health.
- **Key Features**:
  - Summary metric tiles for active locations, transport connections, system readiness, and latest capacity.
  - Direct quick-action navigation cards for **Urgent Tea Collection Dispatch (Port 8082)**, **Daily Throughput (Port 8080)**, and **Critical Bottlenecks**.

## 🚀 Step-by-Step How-To-Work Guide

### Step 1: Start PostgreSQL Database
```powershell
cd sys/AgriPulse_Backend
docker compose up -d
```

### Step 2: Start Spring Boot Backend Services
In a terminal window, run your Dispatch Engine backend on port `8082`:
```powershell
cd sys/AgriPulse_Backend
mvn spring-boot:run
```

### Step 3: Install Frontend Node Modules (If not already installed)
```powershell
cd sys/AgriPulse_Frontend
npm install
```

### Step 4: Launch Frontend Dev Server
```powershell
cd sys/AgriPulse_Frontend
npm run dev
```

Open browser at `http://localhost:5173/`.

### Step 5: Test Full Workflow
1. Navigate to **`http://localhost:5173/dispatch`**.
2. Click **"Reset / Seed Database"** to populate initial database records.
3. Observe the calculated path to batch **B-102** at **C6**.
4. Click **"Mark Batch as Collected"** to collect batch B-102 and watch the truck auto-route to batch **B-091** at **C4**.
5. Navigate to **Road Hazard Control (`/dispatch/roads`)**, click **"Close Road"** on segment C1-C2, and return to Live Dispatch to observe automatic rerouting!

## ❓ Troubleshooting & Gotchas

1. **`ECONNREFUSED` Error in Vite Console**:
   - **Reason**: The frontend is attempting to send requests to `localhost:8082`, `localhost:8081`, or `localhost:8080`, but the corresponding Spring Boot backend is not running yet.
   - **Solution**: Start the Spring Boot backend service using `mvn spring-boot:run` in a separate terminal.

2. **`'vite' is not recognized` Error**:
   - **Reason**: `npm install` was not executed inside `AgriPulse_Frontend`.
   - **Solution**: Run `npm install` inside the `AgriPulse_Frontend` folder.
